# 开发规范

## 产品形态

- 本地桌面应用。解析、索引、查询、转换、生成都在本机完成，数据不离开机器。
- 窗口默认 1440×900，最小 960×640，居中打开。
- 使用无系统标题栏的自定义窗口（`decorations: false`），自绘拖拽区和最小化、最大化、关闭按钮。
- 界面语言默认中文。菜单、按钮、状态栏、空状态、错误提示都用中文短句。

## 技术栈

| 层 | 选择 |
| --- | --- |
| 外壳 | Tauri 2 |
| 重计算 | Rust，`src-tauri/` |
| 界面 | TypeScript + Vite，不引入 UI 组件库 |
| 编辑器 | CodeMirror 6 |
| 样式 | 一份手写 CSS，用 CSS 变量，不用预处理器 |

包管理用 npm。前端脚本保持 `dev`、`build`、`preview`、`tauri`。版本号以 `package.json` 为准，Tauri 配置引用 `../package.json`。

## 目录

```
index.html          窗口骨架
src/main.ts         界面状态与交互
src/styles.css      全部样式
src/assets/         logo
src-tauri/src/      Rust 命令与领域逻辑
design-system/      本规范，不参与构建
```

领域代码放 Rust 模块，不把解析和大体量计算写进 WebView。一个模块只做一件事，例如解析、索引、查询、转换。前端通过 `invoke` 调用 `snake_case` 命令，返回字段用 `camelCase`。

## 前后端分工

- Rust 负责读文件、解析、校验、搜索、生成、导出数据。
- WebView 只负责渲染当前视口、编辑器、菜单和状态。大结果不要整份灌进 DOM。
- 命令返回 `Result`，前端把错误写成状态栏或面板里的短句，不用弹系统对话框堆错误。
- 文档内容保持输入顺序。解析 JSON 时启用 `serde_json` 的 `preserve_order`，不要按键名排序。

## 交互

- 菜单挂在标题栏左侧：文件、工具、帮助。菜单项带快捷键时，快捷键靠右，用 `<kbd>`。
- 常用编辑动作放编辑器上方的工具条，不重复塞进工具菜单。
- 主工作区左右分栏，中间 6px 分隔条可拖动。右栏用横向页签切换视图，页签文字必须横排。
- 单击执行，危险动作才二次确认。关闭浮层用 Esc，点浮层外部也关闭。
- 拖入文件要有全屏虚线提示。进入某种模式后再拖入，提示文案要说明文件会进哪里。
- 搜索、对比、实时解析都要防抖，并丢掉过期请求的结果。
- 状态栏左侧是文件名、有效性和统计；右侧是版本、模式、导出、主题和全屏。

## 代码风格

- TypeScript 打开 `strict`，不留未使用变量。
- 用户能点到的文案用中文；代码标识符用英文。
- 样式类名用短横线，状态类用 `hidden`、`active`、`error`。
- 注释只解释非显而易见的限制，不复述代码。
